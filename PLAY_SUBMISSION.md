# Dombelz — Play Store submission reference

Everything here is domain-independent. `MOBILE_APP_GUIDE.md` covers the full
playbook; this file is the material you paste into Play Console plus the
commands you run once a domain is settled.

---

## 0. The two things you can never change

| Value | Set where | Why it's permanent |
|---|---|---|
| `app.dombelz.mobile` | `capacitor.config.ts`, Bubblewrap prompt | Play identifies the app by package name. A different one is a *new listing* — no upgrade path, installs and reviews do not carry over. |
| Signing keystore | Generated by Bubblewrap | **Lose it and the listing can never be updated again.** Back up the `.keystore` file and its passwords off this machine before you upload anything. |

The **domain is not** on this list. A TWA points at a URL; changing it is a
normal versioned update. See §4.

## 2. Digital Asset Links

Placeholder committed at `public/.well-known/assetlinks.json`, verified to
survive both `npm run build` and the Vercel copy step.

After `bubblewrap init`, read the SHA-256 fingerprint it prints (or
`keytool -list -v -keystore android.keystore`) and replace
`REPLACE_WITH_SHA256_FROM_BUBBLEWRAP`. Colon-separated uppercase hex, e.g.
`AB:CD:12:…`.

**If you use Play App Signing** — and you should — Google re-signs the upload
with *its own* key. The fingerprint that must appear here is the one from
**Play Console → Setup → App integrity → App signing key certificate**, not
your local upload key. Getting this wrong is the single most common reason the
browser address bar refuses to disappear.

Both fingerprints can be listed at once; that is the usual setup.

Verify after deploying:

```bash
curl https://YOUR-DOMAIN/.well-known/assetlinks.json
```

## 3. Data safety form

Truthful answers for this codebase. Play rejects submissions that
under-declare, and the health data question is one they actively check.

| Question | Answer |
|---|---|
| Does the app collect or share user data? | **Yes, collects. Does not share.** |
| Is data encrypted in transit? | **Yes** — HTTPS throughout, Supabase enforces TLS |
| Can users request deletion? | **Yes** — Profile → Settings → Danger zone |
| Is all collected data optional? | **No** — account data is required |

**Data types to declare:**

| Category | Type | Collected | Required | Purpose |
|---|---|---|---|---|
| Personal info | Name | Yes | Yes | Account management, app functionality |
| Personal info | Email address | Yes | Yes | Account management |
| Health & fitness | Health info | Yes | Yes | App functionality — weight, BMI, calories, macros |
| Health & fitness | Fitness info | Yes | Yes | App functionality — workouts, streaks |
| Photos & videos | Photos | Yes | No | App functionality — progress photos, food recognition |
| App activity | Other user-generated content | Yes | No | App functionality — food and water logs |

**Third-party processing to disclose:** food photos and text prompts are sent
to Groq for AI inference. Declare as processing, not sharing — it is a
processor acting on your behalf, not an independent recipient.

⚠️ **Do not declare "Data is not collected."** The app stores named users'
health metrics.

## 4. Changing the domain later

The preview alias is fine for internal testing. When the real domain is ready:

1. Point DNS at Vercel, confirm the site loads over HTTPS.
2. Serve `assetlinks.json` on the **new** domain with the same fingerprints.
3. `bubblewrap init` against the new manifest URL — **same keystore, same
   package name**.
4. Bump `versionCode`, rebuild, upload as an update.

Users keep their install and data. Nothing in Play resets.

⚠️ A TWA loads its URL live. If `claude_edits` is deleted, the branch alias
stops resolving and anyone with the app installed sees an error page. Keep the
branch alive for as long as any test build points at it.

## 7. Commands, once the domain is chosen

```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://YOUR-DOMAIN/manifest.webmanifest
# package id: app.dombelz.mobile · name: Dombelz · display: standalone
bubblewrap build      # → app-release-bundle.aab
```

Needs a JDK and Android SDK; Bubblewrap offers to fetch both on first run. The
prompts are interactive, so this runs on your machine rather than through me.

Then: Play Console → Create app → Internal testing → upload the `.aab` → add
your own account as a tester. Internal testing has no review wait, so you can
install on a real device within minutes.
